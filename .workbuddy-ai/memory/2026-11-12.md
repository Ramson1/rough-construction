# 2026-11-12

Studied `roblox game.html` (1695 lines, single self-contained file; identical copy also at Downloads).
Vortex / "Black - Box Games & Baseplate" — Roblox-style browser game.

- Stack: vanilla HTML/CSS/JS, Three.js r128 + OrbitControls (CDN), PeerJS 1.5.2 (WebRTC), MQTT over WSS to public `test.mosquitto.org:8081` on topic `retro_roblox_baseplate_servers_2026`, plus `BroadcastChannel('retro_roblox_local_bus')` for same-origin tabs. No build step, no backend, no bundler.
- Flow: signup -> dashboard (Home / Avatar / Inbox tabs) -> Classic Baseplate server browser -> create/join -> 3D game with HUD, chat, player list -> settings (Resume / Leave = reload).
- Persistence: `localStorage.retro_roblox_account` and `localStorage.vortex_friends_list`. Password/email collected but never stored or used; no auth.
- Avatars are procedurally drawn 2D canvas images (headshot/full-body) for UI and procedural Three.js meshes in-world. Three genders: male (blocky), female (3.0 woman, hair tuft, trans-flag badge, boots), custom (falls through to male everywhere). Torso/legs colors customizable.
- World: 100x100 stud-textured baseplate, sky-blue fog, ambient + directional light, 3rd-person OrbitControls follow camera, WASD/arrows + Space jump, procedural walk cycle + idle bob. No collision or world bounds.
- Net: host-authoritative relay (`relayToAllClients`), 2s MQTT/BroadcastChannel host pings, per-frame position/rotation/legRot payloads, remote lerp smoothing. Chat via peer connections + BroadcastChannel with in-world canvas-texture bubbles.

Known landmines (verified, not yet fixed):
- `graphics-quality-select` has no event handler; Energy currency never increments; friend status always "Offline"; inbox static.
- Face texture never renders on head: `buildAvatarMesh` uses a 6-material BoxGeometry-style array but `createRoundedBox` returns ExtrudeGeometry with only 2 material groups.
- `rp.targetRotY` is set but never applied in `animate()` -> remote players never rotate.
- `discoveredServers` entries never expire despite `lastSeen` -> stale servers + inflated online counts.
- `escapeHtml` escapes only & < > (not quotes); chat `sender` is injected via innerHTML unescaped, and inline onclick interpolates usernames -> XSS/injection.
- `ctx.roundRect` needs modern browsers; no CDN/offline fallback; no `peer.on('error')` or MQTT error handler.
- `sunLight.target` is moved but never added to the scene.
- Chat can duplicate when both PeerJS and BroadcastChannel deliver the same message (same-origin multi-tab).
